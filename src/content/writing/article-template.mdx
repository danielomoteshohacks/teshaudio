## Why level matters

When two versions of the same audio differ in level, listeners tend to prefer the louder one, even when the difference is small. Louder playback is perceived as fuller and more detailed, because the ear's sensitivity to low and high frequencies changes with level. A fair comparison therefore has to remove the level difference first.

> A comparison that is not level-matched mostly measures volume.

### Integrated loudness

Integrated loudness, measured in LUFS, summarises the perceived loudness of a whole file as one number. The measurement applies a frequency weighting, then averages energy in overlapping blocks, ignoring silence and very quiet passages through gating.<Sidenote>The method is defined in ITU-R BS.1770 [1]; EBU R 128 [2] builds broadcast loudness normalisation on top of it.</Sidenote>

## Computing the gain

Given two measured loudness values, the player turns the louder version down to the quieter one. The gain in decibels is the difference between them, converted to a linear multiplier:

$$
g = 10^{\frac{L_\text{target} - L_\text{version}}{20}}, \qquad L_\text{target} = \min(L_A, L_B)
$$

With $L_A = -24$ and $L_B = -16$ LUFS, version B receives $-8$ dB, a linear gain of about $0.40$. Nothing is ever boosted, which avoids pushing peaks into clipping.

```ts
// Gain for one version, in linear terms.
const dbToGain = (db: number) => 10 ** (db / 20);
const target = Math.min(lufsA, lufsB);
const gainB = dbToGain(target - lufsB); // -8 dB -> 0.398
```

| Version | Measured | Gain applied | Played at |
| ------- | -------: | -----------: | --------: |
| A       | −24.0 LUFS | 0.0 dB | −24.0 LUFS |
| B       | −16.0 LUFS | −8.0 dB | −24.0 LUFS |

- Turn the louder version down by the difference.
- Switch between versions without stopping either one.
